API reference

Everything the RegMap web app does is available over a JSON HTTP API on the same origin. Push a control set, pull ranked mappings, save projects, and export audit-ready packages, all programmatically.

Authentication

Create an account, then mint an API key and send it as a Bearer token. Browser sessions use an HttpOnly cookie instead; both resolve to the same account.

POST/auth/keys
Create an API key (shown once). Requires an authenticated session.
# create a key, then use it as a Bearer token
curl -X POST https://YOUR_HOST/auth/keys \
  -H "content-type: application/json" -b cookies.txt \
  -d '{"label":"ci"}'

curl https://YOUR_HOST/me -H "Authorization: Bearer rk_live_..."
Keys carry scopes. Keep them server-side; anything in a browser is readable by any script on the origin, so the app uses the session cookie there, not a key.

Base URL & format

All endpoints are JSON over the same origin that serves the app. Errors return an HTTP status and a {"detail": "..."} body. Amounts of model work are metered in Compute Units and reported in x-regmap-compute-units response headers.

Map a control

POST/map
Rank the controls in a target framework that best match one control or a free-text query.
FieldTypeNotes
targetstringtarget framework id (see /frameworks)
sourcestring?source framework id (for an official comparison)
source_idstring?a control id in the source, or omit and use text
textstring?free-text control description
top_kint1 to 25, default 5
curl -X POST https://YOUR_HOST/map \
  -H "content-type: application/json" -H "Authorization: Bearer rk_..." \
  -d '{"target":"nist_80053","text":"encrypt data at rest","top_k":3}'
Each result has id, title, score, official, and why (the shared salient terms).

Coverage & gaps

POST/map/bulk
Map a whole source framework onto a target and get coverage plus the official gap list.
curl -X POST https://YOUR_HOST/map/bulk \
  -H "content-type: application/json" -H "Authorization: Bearer rk_..." \
  -d '{"source":"hipaa_security","target":"nist_80053","top_k":5}'

Your framework

POST/map/custom
Map your own control set onto a catalog framework. Results are model suggestions for review.
curl -X POST https://YOUR_HOST/map/custom \
  -H "content-type: application/json" -H "Authorization: Bearer rk_..." \
  -d '{"target":"nist_80053","top_k":5,
       "controls":[{"id":"AC-1","text":"Access control policy and procedures"}]}'

Multi-target coverage

POST/map/custom/multi
Map one control set onto several frameworks at once; returns the best match per framework and a coverage summary.
curl -X POST https://YOUR_HOST/map/custom/multi \
  -H "content-type: application/json" -H "Authorization: Bearer rk_..." \
  -d '{"targets":["nist_80053","hipaa_security"],
       "controls":[{"id":"P-1","text":"MFA is required for all access"}]}'

Remediation guidance

POST/remediate
A starter policy statement and implementation checklist for a target control (a gap). A draft to adapt, not legal advice.
curl -X POST https://YOUR_HOST/remediate \
  -H "content-type: application/json" -H "Authorization: Bearer rk_..." \
  -d '{"target":"nist_80053","control_id":"AC-2"}'

Frameworks

GET/frameworks
Every framework, with control counts, availability, and planned (coming-soon) counts.
GET/frameworks/{id}/controls
The controls in a framework. Add ?include_text=true for full text.

Pairs

GET/pairs
Every framework pair this instance can answer, and by what route (official, inverted, derived).

Projects

A project is a saved crosswalk: the control set, target, and every decision, status, note, and evidence link. All project endpoints require an account.

GET/projects
Your projects plus those shared with you ({projects, shared}).
POST/projects
Create a project. Body: {name, target_fid, source_kind, data}.
GET/projects/{id}
Fetch a project (owner or a member); includes your role.
PUT/projects/{id}
Update (owner or editor). Rename with {name}.
DELETE/projects/{id}
Delete a project (owner only).

Export

GET/projects/{id}/export?fmt=json|csv|xlsx|docx
An audit-ready package, one row per control with status, accepted/rejected targets, evidence, and note.

Drift & monitoring

GET/projects/{id}/drift
Whether the target framework changed since the project was saved, plus any stale mappings.
POST/projects/{id}/recheck
Re-run the crosswalk against the current catalog now and record the result.
POST/monitor/run
Re-check every monitored project that is due. Call on a schedule (cron / k8s CronJob).

Collaboration

GETPOSTDELETE/projects/{id}/members
List, invite (by email + role: editor / commenter / viewer), or remove collaborators (owner manages).
GETPOST/projects/{id}/comments
Read or add comments. Body: {body, anchor?} where anchor is a source control id.

Deploy

Run it anywhere

One image carries the API, this website, and the fine-tuned model. It runs on a laptop, a single VM, or Kubernetes, on CPU or GPU. The model is baked in and the container runs offline as a non-root user.

Container

Build and run

docker build -f regmap_engine/docker/Dockerfile \
  -t regmap-engine:0.2 .          # from the repo root

docker run --rm -p 8000:8000 regmap-engine:0.2
#   UI   http://localhost:8000/
#   API  http://localhost:8000/docs

CPU-only or pinned CUDA

# slim CPU image
--build-arg \
  TORCH_INDEX=https://download.pytorch.org/whl/cpu

# pinned CUDA build
--build-arg \
  TORCH_INDEX=https://download.pytorch.org/whl/cu121

The default image is GPU-capable and also runs on CPU. Without the model present the service still answers on TF-IDF.

Kubernetes

Apply the manifests

kubectl apply -k regmap_engine/k8s

kubectl -n regmap port-forward \
  svc/regmap-engine 8010:80

Deployment · Service · HPA · NetworkPolicy, as a kustomization. The image reference is digest-pinned.

Optional tiers

GPU — an opt-in Deployment for a GPU node pool.
KEDA — scale-to-zero so an idle GPU costs nothing.

Both manifests exist but are untested: they need real GPU hardware, which the current environment does not have.

Configuration

VariableDefaultWhat it does
REGMAP_MODEL../models/regmap-embedder Embedder to load. If it fails, the engine degrades to TF-IDF rather than refusing to start.
REGMAP_DEVICEauto Force cpu or cuda. Auto-selects CUDA when visible.
REGMAP_LICENSED(empty) Comma-separated framework ids the operator holds a licence for. Default-deny: licensed frameworks are refused with 403 until listed here.
REGMAP_GPU_CU_MULT8 GPU-second to CPU-second ratio for the compute meter.
REGMAP_ENGINE_VERSION0.2 Stamped onto every response for reproducibility.
DATABASE_URLsqlite:///./regmap.db Billing ledger. Must be Postgres in production — SQLite is destroyed on restart and is per-replica, so usage records would be silently lost.
REGMAP_REQUIRE_AUTHfalse Enforce API keys. Left off by default so the self-hosted tier keeps working unchanged; set true for the hosted service. Admin endpoints are refused either way.
REGMAP_BULK_MAX150 Controls per /map/bulk call.
REGMAP_RATE_BULK10 Requests/minute per key for /map/bulk (REGMAP_RATE_EVAL defaults to 4).

Metering and access control

The engine now has a billing spine: accounts, hashed API keys with scopes, per-account usage recorded to an immutable ledger, and monthly quotas enforced before work runs.

Deterministic Compute Units

A charge is a function of the request — how many encodes, against how large a corpus — not of elapsed time. The same call always costs the same, so a bill is predictable and a price per call can be published. See /pricing.

Auditable ledger

Every billable request writes an immutable event and increments a period counter in one transaction. The events are the source of truth, so any counter can be rebuilt from them via /admin/reconcile.

Quotas before work

Admission is decided from an estimate, so an out-of-allowance caller gets 402 without consuming compute. Plans may permit metered overage.

Still outstanding

No payment capture

The ledger computes what is owed, including overage, but nothing charges a card. Stripe integration and self-serve signup are the next phase.

Rate limiting is per replica

An in-process token bucket, so with N replicas a caller effectively gets N times the limit. Honest protection against a runaway script; real multi-tenant limiting needs shared state.

Postgres required in production

The default SQLite ledger lives in the container's writable layer and this Deployment mounts no volume — it is destroyed on restart and is per-replica. Set DATABASE_URL before charging anyone.
